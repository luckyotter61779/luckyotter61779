# Hey, I'm luckyotter

I spend most of my time writing Python scripts that make repetitive tasks disappear. Whether it's batch-processing logs, wiring up simple APIs, or keeping a fleet of Linux boxes in sync, I like tools that stay out of the way and just work.

## What I actually do

- **Python & automation** — small, focused scripts that handle the boring parts of the day so I can focus on the interesting ones. I prefer readability over clever one-liners.
- **Linux day-to-day** — comfortable living in the terminal, writing systemd units, and keeping systems lean. Most of my machines run Debian or a close relative.
- **Open source habits** — I read more code than I write, contribute when something is broken or missing, and try to leave useful notes for the next person.

## How I approach problems

Start simple. Measure what actually matters. Automate the parts that hurt. Document just enough so future-me (or anyone else) doesn't have to reverse-engineer it three months later.

I keep a running list of small utilities and experiments in public repos. Nothing flashy—just practical things that solved a real need at the time.

## Currently exploring

- Better ways to orchestrate background jobs without adding heavy frameworks
- Lightweight monitoring that doesn't require a full observability stack
- Clean patterns for packaging CLI tools so they install and update without drama

If you maintain something similar or are wrestling with the same kinds of problems, feel free to open an issue or drop a note. I'm always happy to trade ideas or pair on a small fix.
